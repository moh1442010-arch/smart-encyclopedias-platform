# خطة مراجعة الخبراء والعملاء — المحاسب الميزان
تاريخ إعداد الخطة: 2026-10-17  
الحالة: **خطة قبول واختبار؛ ليست شهادة اجتياز ولا إعلان جاهزية للبيع.**

## 1. الهدف
جمع أدلة قابلة للتتبع من ثلاث جهات منفصلة:
1. **المراجعة الفنية:** مطور/مراجع Android مستقل يراجع الأعطال والتحديثات والتوقيع والخصوصية.
2. **المراجعة المحاسبية:** محاسب ممارس يطابق القيود والأرصدة والتقارير مع نتائج مرجعية مستقلة.
3. **تجربة العملاء:** مستخدمون من أنشطة صغيرة ومتوسطة يختبرون المهام اليومية ثم يقدمون رأيًا صريحًا، إيجابيًا أو سلبيًا.

لا تُستخدم آراء مصطنعة، ولا تنشر أسماء أو تقييمات دون موافقة واضحة. لا تُعرض نتيجة «نجاح» قبل حفظ دليلها.

## 2. بوابة صفر — تثبيت النسخة محل الاختبار
قبل أي تقييم بشري، يسجل المسؤول:
- رابط GitHub Actions ورقم التشغيل وحالته.
- SHA الالتزام البرمجي الذي بُني منه الملف.
- اسم الإصدار وversionCode واسم الحزمة.
- بصمة شهادة التوقيع وSHA-256 لملف APK/AAB.
- الجهاز وإصدار Android، وهل الاختبار تثبيت جديد أم تحديث فوق النسخة السابقة.
- عدم طلب حذف النسخة الحالية قبل اجتياز اختبار التحديث والمحافظة على البيانات.

**مانع إطلاق:** أي عدم تطابق في التوقيع أو هوية الحزمة أو رقم الإصدار، أو انهيار عند تسجيل الدخول، يوقف تجربة العملاء المدفوعة.

## 3. المراجعة الفنية المستقلة
يجب أن يسجل المراجع لكل بند: Pass / Fail / Blocked، والخطوات، والنتيجة المتوقعة والفعلية، ودليلًا منقحًا من البيانات الشخصية.

- التثبيت الجديد، التحديث فوق النسخة السابقة، أول تشغيل، تسجيل الدخول والخروج.
- اختبار PIN صحيح وخاطئ، وحقول فارغة/غير صالحة، ومنع الانهيار بعد الضغط على الدخول.
- الرجوع من كل شاشة والعودة للرئيسية؛ اختبار تدوير الشاشة واستئناف التطبيق بعد إغلاقه.
- اختبار Android 16 على Samsung SM-A165F، ثم جهاز Android آخر إن توفر.
- العمل دون اتصال، وانقطاع الاتصال أثناء عمليات الترخيص أو الاستعلام.
- صلاحيات التطبيق، كشف الأسرار في السجلات، التعامل مع النسخ الاحتياطية، وعدم تسريب البيانات الحساسة.
- التحقق من شهادة التوقيع وثباتها عبر الإصدارات، وSHA-256، وصحة APK/AAB.
- اختبار قاعدة بيانات قديمة، ترقية المخطط، نسخة تالفة، مساحة تخزين منخفضة، وإيقاف التطبيق أثناء العملية.

لا تعتبر اختبارات الوحدة وحدها بديلًا عن اختبار الجهاز الحقيقي.

## 4. المراجعة المحاسبية بأرقام مرجعية
يُنشئ المحاسب ورقة حساب خارج التطبيق، ثم يطابق النتائج بعد كل عملية. تستخدم بيانات تجريبية فقط.

| الحالة | تحقق إلزامي |
|---|---|
| رصيد افتتاحي | مجموع المدين = مجموع الدائن؛ الأرصدة الافتتاحية مطابقة |
| شراء مخزون نقدًا | زيادة الكمية والتكلفة؛ انخفاض الصندوق؛ القيد متوازن |
| شراء آجل | زيادة المخزون/التكلفة وزيادة رصيد المورد |
| بيع نقدي | انخفاض المخزون، زيادة الصندوق، إثبات الإيراد وتكلفة البضاعة والربح |
| بيع آجل وجزئي | رصيد العميل = الفاتورة − المقبوضات؛ الصندوق يساوي المقبوض الفعلي |
| مردود بيع وشراء | عكس الكميات والأرصدة والقيود وفق سياسة محاسبية واضحة |
| مصروف ورواتب وسلفة | حساب المصروف/الالتزام والصندوق/البنك ورصيد الموظف صحيح |
| تحصيل/سداد موزع | توزيع المبلغ على الفواتير لا يكرر القبض ولا يترك رصيدًا خاطئًا |
| إلغاء/عكس قيد | أثر عكسي قابل للتتبع؛ لا حذف صامت لحركة مرحّلة |
| تقارير | الأستاذ وميزان المراجعة والربح والمخزون تطابق دفتر العمليات |
| المبالغ الصغيرة | اختبار فرق وحدة نقدية واحدة وحدود التقريب؛ لا فروق مخفية |
| نسخ واستعادة | استعادة كل الجداول والإعدادات دون فقد أو تكرار، مع تحقق سلامة النسخة |

أي فرق مالي، أو قيد غير متوازن، أو مخزون سالب غير مفسر، أو تقرير لا يطابق السجل، يعد فشلًا مانعًا للإطلاق حتى تفسيره وإصلاحه.

## 5. تجربة العملاء المحدودة
بعد اجتياز البوابتين الفنية والمحاسبية فقط:
- اختيار 3–5 مستخدمين تجريبيين من أنشطة مختلفة، بموافقتهم، وببيانات وهمية أو غير حساسة.
- إرشادهم إلى تنفيذ مهام محددة دون تلقينهم الإجابة أو مطالبتهم بتقييم إيجابي.
- مراقبة الوقت والأخطاء ومواضع الالتباس، ثم إجراء مقابلة قصيرة.
- توثيق كل ملاحظة بمعرف، وشدة، وخطوات إعادة الإنتاج، وقرار (إصلاح/توضيح/مؤجل مع سبب).
- عدم جمع كلمات مرور أو أرقام حسابات أو بيانات مالية حقيقية في نماذج الملاحظات.

### أسئلة العملاء
1. هل استطعت تثبيت التطبيق والدخول إليه دون مساعدة؟
2. ما أول مهمة حاولت تنفيذها؟ وهل أكملتها؟
3. هل أسماء الحسابات والأزرار مفهومة بالعربية؟ وهل الرجوع إلى الرئيسية واضح؟
4. هل تطابقت الفاتورة والمخزون والصندوق ورصيد العميل/المورد بعد العملية؟
5. هل فهمت التقارير والفواتير المطبوعة أو المصدرة؟
6. هل كانت هناك بطء أو إغلاق مفاجئ أو فقد بيانات؟
7. ما أهم ميزة ناقصة؟ وما أكثر شيء أربكك؟
8. ما مدى ثقتك في استخدامه بعد اختبار محدود، وما سبب تقييمك؟
9. هل توافق صراحة على نشر رأيك باسم مستعار؟ (نعم/لا)

لا تحول إجابات الاختبار إلى تقييمات منشورة دون موافقة صريحة، ولا تخفِ الملاحظات السلبية.

## 7. معايير قرار الإطلاق
لا يوصى بالبيع العام إلا بعد:
- عدم وجود عيوب Critical أو High مفتوحة.
- اجتياز الدخول والتثبيت والتحديث على جهاز حقيقي.
- اجتياز جميع حالات الاختبار المحاسبي المرجعية وتوثيق النتائج.
- نجاح النسخ الاحتياطي والاستعادة والترقية، وتوثيق نموذج حماية البيانات بصدق.
- اختبار الترخيص والاشتراك وانتهاء المدة والتجديد والاسترداد عمليًا.
- اختبار Windows فعليًا قبل الإعلان عن توفر نسخة Windows.
- توحيد الأسعار وسياسة الدعم والخصوصية والاسترداد، وفتح الدفع فقط عند الجاهزية.
- مراجعة آراء العملاء وتسجيل الإصلاحات، دون اختلاق شهادات أو نسب رضا.

## 8. حالة الأدلة عند إنشاء هذه الخطة
- توجد سجلات بناء Android سابقة ناجحة، لكنها لا تثبت أن أحدث تعديلات إصلاح PIN قد بُنيت واختُبرت على الجهاز.
- عطل الإغلاق بعد الدخول لم يُثبت حله بعد.
- اكتمال الترخيص التجاري والدفع والاختبارات المحاسبية الشاملة وWindows غير مثبت.
- لذلك تظل الحالة **قيد التحقق — لا تعتمد للبيع العام بعد**.
