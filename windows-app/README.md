# شركة محمد مصطفى الذكية — Windows x64

تطبيق مكتبي Windows مبني باستخدام .NET 8 Windows Forms وSQLite. الواجهة عربية مع خيار اللغة الإنجليزية، والتطبيق يُنشر ذاتيًا مع مكونات التشغيل اللازمة.

## الوحدات الموجودة حاليًا
- الأصناف والمخزون مع إدخال الباركود يدويًا أو عبر ماسح USB/Bluetooth الذي يعمل كلوحة مفاتيح.
- تسجيل المبيعات والمشتريات وتحديث الكمية داخل معاملة قاعدة بيانات.
- العملاء والموردون.
- الموظفون والرواتب الأساسية والسلف والخصومات.
- المصروفات.
- تصدير واستعادة نسخة SQLite مع فحص سلامة الملف قبل الاستعادة.
- ملخص تشغيلي وطباعة التقرير وإرساله بالبريد الإلكتروني.
- دعم العربية والإنجليزية.

## البناء والتنزيل
يُبنى إصدار Windows x64 بواسطة GitHub Actions في الملف `.github/workflows/build-windows-app.yml`. مخرجات البناء تشمل EXE مستقلًا، وZIP، وبصمة SHA-256. افتح تبويب Actions في المستودع، واختر أحدث تشغيل ناجح بعنوان Build Smart Company Windows App، ثم نزّل artifact الذي يبدأ اسمه بـ `smart-company-windows`.

## مكان قاعدة البيانات
`%LOCALAPPDATA%\SmartCompany\smartcompany.db`

## دفتر الأستاذ — ترحيل العمليات المدعومة
أضيفت شاشة «دفتر الأستاذ وميزان المراجعة» لعرض أرصدة الحسابات المسجلة ومقارنة إجمالي المدين والدائن، مع عدّاد للعمليات القديمة التي لا يوجد لها قيد مرتبط في دفتر الأستاذ. أُضيفت كذلك حسابات أساسية للذمم المدينة والدائنة والرواتب ضمن دليل الحسابات.

**الدورة المحاسبية لم تكتمل بعد.** تُرحّل الآن العمليات الجديدة المدعومة للمبيعات والمشتريات النقدية والآجلة، والتحصيل والسداد، والمصروفات، ومرتجعات البيع والشراء، واستحقاق الراتب والسلف وتسويته. تُسجّل الخصومات الجديدة بعد ترحيل استحقاق الراتب فقط، بقيد مدين للرواتب المستحقة ودائن لالتزامات الخصومات؛ ويُخفض صرف الراتب بقيمة الخصومات. لا تُنشأ قيود تاريخية تلقائيًا قبل تحديد طريقة السداد والطرف المرتبط بكل عملية قديمة. قد تظل السجلات التاريخية بلا قيود وتظهر في التشخيص. التغييرات في المخطط إضافية ولا تحذف جداول المستخدمين أو معاملاتهم.

## حدود الإصدار — مهمة
هذه نسخة **ما قبل الإصدار التجاري**. على الرغم من ترحيل عدد أكبر من العمليات الجديدة، لم يثبت بعد اكتمال كل حالات الدورة المحاسبية أو سلامة ترحيل قواعد البيانات القديمة؛ لذلك فإن الفرق الحسابي الظاهر في الملخص ليس صافي ربح محاسبيًا ولا بديلًا عن قوائم مالية معتمدة. كما لم يثبت بعد اختبار جميع السيناريوهات على أجهزة Windows فعلية. لا تستخدمها لإقفال حسابات أو اتخاذ قرارات مالية قبل استكمال دفتر الأستاذ، وترحيل جميع الوحدات، واختبارات محاسبية مستقلة، واختبار النسخ الاحتياطي والاستعادة عمليًا.

## إصدار التطوير 2.2.5
- إضافة حساب التزامات خصومات الرواتب إلى دليل الحسابات.
- منع إدخال خصم راتب قبل ترحيل استحقاق الشهر، ومنع إضافة حركات بعد تسوية الراتب.
- ترحيل الخصم بقيد متوازن والتحقق من أن مجموع السلف والخصومات لا يتجاوز الراتب، ثم تسوية صافي الراتب دون تكرار المصروف.
- إظهار الخصومات التي لا تملك قيدًا ضمن فحص دفتر الأستاذ، مع إبقاء السجلات التاريخية دون تعديل تلقائي.

## توصيات الاختبار
1. اختبر على قاعدة بيانات تجريبية فقط.
2. اختبر بيع كمية أكبر من المخزون؛ يجب رفضه.
3. اختبر شراءً ثم بيعًا وتحقق من رصيد المخزون.
4. صدّر نسخة احتياطية، ثم اختبر استعادتها على قاعدة تجريبية.
5. طابق إجماليات العمليات مع قيود دفتر الأستاذ بعد إكمال الترحيل المحاسبي.
