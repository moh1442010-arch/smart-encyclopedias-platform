# خطة اختبار خبراء Windows — المحاسب الميزان

الحالة: خطة اختبار لمرشح ما قبل الإصدار التجاري. وجود هذه الخطة لا يعني اجتياز الاختبارات أو اعتماد البرنامج.

## 1. بيانات المرشح

- المنصة: Windows x64
- مصدر البناء: المستودع `moh1442010-arch/smart-encyclopedias-platform`
- مسار المشروع: `windows-app/`
- سير البناء: `.github/workflows/build-windows-app.yml`
- الإصدار السابق المنشور في سير البناء: 2.2.8
- إصدار Android للمقارنة: 2.4.3
- لا تفترض تطابق Windows مع Android وظيفيًا أو محاسبيًا. سجل رقم إصدار Windows الفعلي وبصمة SHA-256 من الحزمة التي اختبرتها.

## 2. شروط السلامة قبل الاختبار

- استخدم جهاز Windows تجريبيًا وحساب شركة تجريبيًا فقط.
- لا تدخل بيانات عملاء حقيقية أو كلمات مرور أو بيانات مالية سرية.
- احفظ نسخة احتياطية قبل اختبار الاستعادة أو التحديث.
- سجل نسخة Windows ونسخة نظام التشغيل، وتاريخ الاختبار، واسم الملف، وبصمة SHA-256.
- لا تثبّت حزمة غير موقعة أو لا يمكن التحقق من مصدرها دون مراجعة مسؤول الاختبار.

## 3. اختبارات التثبيت والتشغيل

- [ ] تنزيل ZIP واستخراجه دون أخطاء.
- [ ] التحقق من SHA-256 ومطابقته لملف manifest المرفق.
- [ ] تشغيل EXE على Windows x64 نظيف مع توثيق أي متطلبات ناقصة.
- [ ] التأكد من عدم الإغلاق عند فتح التطبيق والتنقل بين الشاشات.
- [ ] تجربة العربية والإنجليزية واتجاه الواجهة والخطوط.
- [ ] إغلاق التطبيق وفتحه مجددًا والتأكد من بقاء البيانات.
- [ ] اختبار الطباعة الفعلية على طابعة متاحة، إن كانت الوظيفة مطلوبة.
- [ ] اختبار التحديث فوق نسخة أقدم إن وُجدت حزمة سابقة مناسبة، والتأكد من بقاء قاعدة البيانات.

## 4. اختبارات المخزون والمبيعات والمشتريات

- [ ] إنشاء صنف بكمية وتكلفة وسعر معلومين.
- [ ] تسجيل شراء والتحقق من زيادة المخزون والتكلفة.
- [ ] تسجيل بيع نقدي والتحقق من نقص المخزون.
- [ ] تجربة بيع كمية أكبر من المتاح؛ يجب رفضها دون تغيير البيانات.
- [ ] تسجيل بيع آجل وربطه بعميل، ثم مطابقة ذمم العميل.
- [ ] تسجيل شراء آجل وربطه بمورد، ثم مطابقة ذمم المورد.
- [ ] اختبار المرتجعات الجزئية والكاملة ومنع تجاوز الكمية الأصلية.
- [ ] التحقق من تكلفة المخزون وتكلفة البضاعة المباعة بعد البيع والمرتجع.

## 5. اختبارات العملاء والموردين والموارد البشرية

- [ ] إنشاء عميل ومورد والتحقق من ظهور بياناتهما في العمليات والتقارير.
- [ ] تسجيل تحصيل من عميل وسداد لمورد ومطابقة الرصيد بعد كل عملية.
- [ ] إنشاء موظف وتجربة الراتب والسلفة والخصم والتسوية.
- [ ] مراجعة طريقة حساب صافي المستحق ومقارنته يدويًا.
- [ ] تسجيل مصروف والتحقق من ظهوره في السجل والتقارير.

## 6. اختبارات دفتر الأستاذ والقوائم المالية

- [ ] التحقق من توازن كل قيد: مجموع المدين يساوي مجموع الدائن.
- [ ] مطابقة دفتر الأستاذ مع كل عملية جديدة مدعومة.
- [ ] فحص عدد العمليات القديمة التي لا تملك قيدًا محاسبيًا مرتبطًا.
- [ ] مطابقة أرصدة العملاء والموردين والنقد والمخزون مع الأستاذ العام.
- [ ] التحقق من أن قائمة الدخل والميزانية وميزان المراجعة لا تعرض نتائج غير مكتملة على أنها معتمدة.
- [ ] لا تعتمد نتائج القوائم المالية حتى يثبت ترحيل جميع أنواع العمليات وتسوياتها وإقفالها.

## 7. اختبارات القيد العكسي

- [ ] أنشئ قيدًا يدويًا متوازنًا من سطرين، ثم اختره وأنشئ قيدًا عكسيًا مع سبب واضح.
- [ ] تحقق من أن المدين في القيد الأصلي يصبح دائنًا بالقيمة نفسها والعكس.
- [ ] تحقق من بقاء القيد الأصلي دون تعديل ومن تسجيل رابط الأصل والعكس وسبب العكس.
- [ ] حاول عكس القيد الأصلي مرة ثانية؛ يجب منع التكرار.
- [ ] حاول عكس قيد عكسي؛ يجب رفض العملية.
- [ ] تحقق من أن شاشة العكس تعرض القيود اليدوية فقط، ولا تعرض قيود المبيعات والمشتريات والمصروفات والرواتب والتحصيلات والمرتجعات؛ تُصحح هذه العمليات من وحداتها الأصلية.
- [ ] اختبر قيدًا غير متوازن أو بيانات تالفة؛ يجب إيقاف العملية دون تغييرات جزئية.
- [ ] طابق دفتر الأستاذ وميزان المراجعة قبل العكس وبعده.

## 8. النسخ الاحتياطي والاستعادة

- [ ] تصدير نسخة احتياطية من قاعدة اختبار.
- [ ] استعادة النسخة إلى قاعدة اختبار منفصلة والتحقق من عدد السجلات والأرصدة.
- [ ] محاولة استعادة ملف تالف أو غير متوافق؛ يجب رفضه دون إفساد قاعدة البيانات الحالية.
- [ ] التأكد من وجود نسخة أمان قبل الاستبدال ومن إمكانية الرجوع إليها.
- [ ] توثيق أن قاعدة البيانات المحلية ليست مشفرة ما لم يثبت العكس باختبار مستقل.

## 9. الترخيص والتجربة والاشتراك

- [ ] التحقق من بداية التجربة المجانية ومدتها بعد إعادة تشغيل التطبيق.
- [ ] اختبار انتهاء التجربة وتفعيل اشتراك صحيح ورفض رمز غير صحيح.
- [ ] اختبار انتهاء الترخيص والتجديد والإلغاء.
- [ ] اختبار سياسة العمل دون اتصال بالإنترنت.
- [ ] التحقق من أن شاشة الأسعار والعملات وأزرار الدعم والدفع تعرض القيم المعتمدة فعليًا.
- [ ] لا تعتمد الحماية من العبث أو صحة الترخيص بمجرد ظهور شاشة الاشتراك.

## 10. نموذج تقرير الخبير

لكل حالة اختبار، سجل:
- رقم الحالة واسمها.
- النتيجة المتوقعة.
- النتيجة الفعلية.
- ناجح / فاشل / لم يُختبر.
- خطوات إعادة إنتاج الخلل.
- صورة أو سجل خطأ بعد إخفاء أي بيانات حساسة.
- درجة الخطورة: حرجة / عالية / متوسطة / منخفضة.

## 11. بوابة الاعتماد

لا يُعلن Windows جاهزًا للاستخدام التجاري إلا بعد:
1. معالجة العيوب الحرجة والعالية وإعادة الاختبارات المتأثرة.
2. إثبات سلامة الدورة المحاسبية الكاملة ومطابقة القوائم.
3. نجاح التثبيت والتحديث والنسخ الاحتياطي والاستعادة على جهاز Windows فعلي.
4. توثيق إصدار الحزمة وcommit المصدر وSHA-256 وحالة التوقيع.
5. فصل ما اجتاز الاختبار عن الوظائف التي لم تُختبر أو لم تكتمل.

حتى إغلاق هذه الشروط، يجب وصف Windows بأنه مرشح للمراجعة التقنية قبل الإصدار التجاري، لا نسخة معتمدة.


## حماية الشاشة — التوقعات الواقعية

- [ ] تحقق من سلوك Windows capture exclusion على إصدار Windows المستخدم.
- [ ] اختبر لقطات الشاشة والتسجيل بأدوات النظام المعتمدة، وسجّل الطرق التي لا تزال تلتقط المحتوى.
- [ ] لا تعتبر الميزة ضمانًا ضد كاميرا خارجية أو أدوات ذات امتيازات عالية أو تسجيل عن بعد.
- [ ] لا تدخل أسرارًا أو مفاتيح خاصة أو بيانات عملاء حقيقية في نسخة المراجعة.
- [ ] لا تعتمد أمن قاعدة البيانات حتى يجري اختبار تشفير فعلي للبيانات المخزنة وإدارة الأسرار.
