# سجل إعادة تأهيل المحاسب الميزان للمخابز — 2.8.2

الحالة: 2.8.2 مرفوض تجارياً. هذا السجل هو مرجع إغلاق العيوب قبل إصدار المراجعة التالي.
خط الأساس التجاري: 2.8.0. الإصدار المستهدف للمراجعة: 2.8.2 مع versionCode أعلى من 280002 عند الحاجة إلى إعادة البناء.
لا حذف لبيانات العملاء، ولا تغيير package ID أو مفتاح التوقيع، ولا اعتماد تجاري قبل اجتياز بوابات القبول.

## أسعار الترخيص المعتمدة

الأسعار لكل جهاز، ولا تعني تضمين مزامنة الفروع أو تعدد الأجهزة.

| العملة | شهري | سنوي | دائم |
|---|---:|---:|---:|
| USD الدولار الأمريكي | 8 | 80 | 199 |
| AED الدرهم الإماراتي | 29 | 290 | 725 |
| SAR الريال السعودي | 29 | 290 | 725 |
| SDG الجنيه السوداني | 55,000 | 550,000 | 1,050,000 |

عملات الترخيص والتحصيل: SDG وUSD وAED وSAR فقط. لا EUR في خيارات الترخيص الجديدة. لا يُعاد تفسير القيود التاريخية أو أرصدة التشغيل بعملة أخرى. يسجل كل طلب عملة السعر، والمبلغ المطلوب، وعملة المبلغ المستلم، وسعر التحويل إن وجد، ومرجع التحويل، وحالة المراجعة اليدوية. لا يفترض أن IBAN سوداني يستقبل كل العملات مباشرة؛ يجب عرض تعليمات التحويل الصحيحة لكل قناة.

## تقسيم التأهيل إلى ثلاث مراحل

### المرحلة الأولى — سلامة المحاسبة وتوحيد الترحيل
بوابة الإغلاق: كل مستند تشغيلي ينتج قيداً واحداً متوازناً وقابلاً للتتبع في دفتر الأستاذ المعتمد، مع منع التكرار، والعكس الموثق، ومطابقة الأستاذ مع الدفاتر الفرعية.

- D01 دفتران: journal_entries/journal_lines مقابل gl_journal_entries/gl_journal_lines.
- D02 عدم وجود جسر ترحيل مثبت لكل عمليات المصنع إلى الأستاذ المؤسسي.
- D03 عدم فرض توازن القيد على مستوى خدمة الترحيل في كل المسارات.
- D04 عدم إثبات الترحيل التلقائي لكل المبيعات.
- D05 عدم إثبات الترحيل التلقائي لكل التحصيلات.
- D06 عدم إثبات الترحيل التلقائي لكل المشتريات.
- D07 عدم إثبات الترحيل التلقائي لكل المصروفات.
- D08 عدم إثبات ترحيل حركات الإنتاج والتصنيع.
- D09 عدم إثبات منع ازدواج القيد عند إعادة المحاولة.
- D10 عدم إثبات مرجع مصدر ثابت لكل قيد.
- D11 عدم اكتمال عكس القيود المرتبطة بالمستندات.
- D12 عدم إثبات إقفال الفترات المالية.
- D13 عدم إثبات منع الترحيل إلى فترة مغلقة.
- D14 عدم إثبات تطابق ميزان المراجعة مع الأستاذ.
- D15 عدم إثبات تطابق حسابات العملاء مع الأستاذ.

## قواعد تسجيل الإغلاق

1. لا يغلق العيب بتعديل نص أو إضافة جدول فقط.
2. لكل عيب: commit SHA، الملفات المتغيرة، اختبار آلي، نتيجة الاختبار، وأثر التحديث على بيانات 2.8.1.
3. الاختبارات التي تحتاج جهازاً حقيقياً تبقى مفتوحة حتى يقدم سجل الجهاز.
4. لا تُستخدم بيانات عميل حقيقية في اختبارات الترحيل أو الاستعادة؛ تستخدم نسخة اختبار مجهولة الهوية.
5. لا يصدر APK مراجعة جديد حتى ينجح بناء الالتزام النهائي واختبارات التثبيت والتحديث والتوقيع.
6. لا يتحول هذا السجل إلى إعلان امتثال ضريبي أو تفوق تجاري دون أدلة مستقلة.
