# دليل تشغيل اشتراكات الميزان للمخابز

**الإصدار المرشح:** 2.6.16  
**معرّف التطبيق:** `com.mohammedmustafa.almizan.bakery`  
**حالة البيع:** لا تفتح البيع قبل نجاح فحص التوقيع الحي واختبار التفعيل على هاتف.

## دورة العميل

1. يفتح العميل صفحة الاشتراك أو شاشة الاشتراك في التطبيق.
2. يختار شهرياً أو سنوياً أو دائماً، ثم يرسل اسمه ووسيلة التواصل ومعرّف الجهاز ومرجع التحويل.
3. يسجل Worker الطلب بحالة `pending`. لا يصدر رمزاً عند إنشاء الطلب.
4. يراجع المسؤول التحويل فعلياً من بنكك، ويقارن المبلغ بالخطة والمرجع وبيانات العميل.
5. يعتمد المسؤول الطلب من لوحة الإدارة. عند الاعتماد فقط يوقع Worker رمز التفعيل ويربطه بمعرّف الجهاز.
6. يرسل المسؤول الرمز للعميل عبر قناة موثقة. يحتفظ العميل بالرمز؛ لا يُنشر في مجموعة عامة.

## الأسعار المعتمدة

| الخطة | السعر |
|---|---:|
| شهري | 55,000 ج.س |
| سنوي | 550,000 ج.س |
| دائم | 1,050,000 ج.س |

- الشهري ينتهي بعد 30 يوماً.
- السنوي ينتهي بعد 365 يوماً.
- الدائم الجديد يستخدم `max_version=any` ويشمل تحديثات التطبيق المستقبلية.
- التراخيص الدائمة القديمة المقيدة بـ2.6.15 تبقى مقبولة للتوافق.
- لا تمنح الخطة الشهرية أو السنوية صلاحية دائمة.

## مفاتيح التوقيع

مفتاح ترخيص التطبيق ليس مفتاح توقيع APK. لا تستخدم ملف `smartcompany-release.jks` أو أي keystore خاص بتوقيع APK بدلاً منه.

1. GitHub Actions يحتاج السر `BAKERY_LICENSE_PRIVATE_KEY_B64`.
2. يمكن أن يحتوي هذا السر على مفتاح الترخيص الخاص بصيغة PEM مباشرة، أو Base64 لمحتوى PEM، أو Base64 لمفتاح DER بصيغة PKCS#8 أو PKCS#1.
3. قبل النشر، يحول سير العمل المفتاح إلى PKCS#8 DER، ويختبر توقيعاً حقيقياً مقابل المفتاح العام المضمّن في التطبيق. إذا لم يتطابق الزوج يتوقف قبل نشر Worker.
4. بعد نجاح المطابقة، يزامن سير العمل المفتاحين إلى Cloudflare باسمَي `LICENSE_PRIVATE_KEY_PKCS8_B64` و`LICENSE_PUBLIC_KEY_DER_B64`.
5. يجب أن توجد كلمة مرور الإدارة في Cloudflare باسم `ADMIN_PASSWORD`، أو الاسم القديم `Admin_BassworD` مؤقتاً. يوصى بتوحيدها على `ADMIN_PASSWORD` وأن تكون 32 حرفاً عشوائياً على الأقل.
6. للتحقق محلياً من ملف المفتاح على Termux دون كشف محتواه، شغّل من جذر المستودع:
   `node tools/validate-bakery-license-key.mjs /المسار/إلى/مفتاح-ترخيص-المخابز.pem $HOME/al-mizan-signing/bakery-license-key.pkcs8.b64`
   يجب أن تظهر `MATCH`. الأداة تحفظ نسخة Base64 بصيغة PKCS#8 بصلاحية خاصة ولا تطبع المفتاح. انسخ محتوى الملف الناتج إلى GitHub Secret باسم `BAKERY_LICENSE_PRIVATE_KEY_B64` فقط بعد ظهور MATCH.
7. إذا ظهرت `NOT MATCH`، لا تستخدم المفتاح. لا تستخدم keystore توقيع APK؛ ابحث عن مفتاح ترخيص المخابز الأصلي المطابق للمفتاح العام داخل التطبيق.
8. لا تضع المفتاح الخاص في المستودع أو التطبيق أو الموقع أو المحادثة أو واتساب. لا تستخدم مفتاح APK لتوقيع تراخيص العملاء.

## قاعدة بيانات التراخيص

- قاعدة D1: `al-mizan-bakery-licenses`.
- مخطط الجداول: `licensing/schema.sql`.
- سير نشر Worker يطبق المخطط باستخدام `CREATE TABLE IF NOT EXISTS` قبل النشر.
- جداول الطلبات وسجل التدقيق يجب أن تكون موجودة في D1 الحية قبل تجربة دورة الطلب والاعتماد.

## اختبار الجاهزية

لا تعتمد البيع إلا بعد اجتياز جميع البنود:

- [ ] فحص `/diagnostics/admin-config` يعيد `adminPasswordConfigured: true`.
- [ ] فحص `/diagnostics/signing-pair` يعيد `signingReady: true` و`signingPairMatches: true`.
- [ ] إرسال طلب تجريبي يظهر بحالة `pending`.
- [ ] رفض طلب غير مدفوع لا يصدر رمزاً.
- [ ] اعتماد طلب تجريبي بعد التحقق من الدفع يصدر رمزاً واحداً فقط.
- [ ] الرمز يعمل على الجهاز المحدد ويرفض جهازاً آخر.
- [ ] الشهري والسنوي ينتهيان حسب المدة، والدائم الجديد يعمل بعد تحديث التطبيق.
- [ ] تحديث 2.6.16 فوق النسخة المثبتة يحافظ على البيانات والتوقيع والترخيص.
- [ ] النسخ الاحتياطي والاستعادة يحافظان على بيانات النشاط.
- [ ] الاختبار اليدوي يؤكد أن هامش الربح يساوي مجموع التحصيلات النقدية وبنكك والديون ناقص تكلفة التشغيل المستهلكة، بما فيها الجاز.
