# بوابة قبول إطلاق المحاسب الميزان — متابعة عيوب لجنة المحاسبين

الحالة: **مفتوحة بالكامل حتى تقديم دليل قابل للتحقق**. هذا الملف قائمة تتبع، وليس شهادة اجتياز. لا تُفتح المبيعات ولا يُعلن الاعتماد قبل إغلاق كل بند ذي صلة.

## قواعد الأدلة
- لكل بند: الالتزام (commit SHA)، رقم البناء، إصدار/بصمة الملف، خطوات الاختبار، النتيجة الفعلية، الجهاز/البيئة، وسجل الأعطال.
- لا يُعد نجاح CI أو المحاكاة بديلاً عن اختبار جهاز أو مراجعة محاسب مستقل.
- لا تُستخدم بيانات عملاء حقيقية في الاختبار. خذ نسخة احتياطية قبل اختبار الترقية والاستعادة.
- تبقى حزم Windows وAndroid موسومة «مرشح تجربة — غير معتمد للبيع» إلى أن يعتمد القرار كتابةً.

## 1. المحاسبة المالية — OPEN
- [ ] اختبارات T1–T8 محددة ومُنفذة على جهاز، مع سجلات قابلة للمراجعة.
- [ ] اختبار مبيعات/مشتريات/مردودات/مخزون/نقدية/عميل/مورد/ضريبة/مصروف/إقفال.
- [ ] ميزان مراجعة متوازن ومطابقة على مستوى أصغر وحدة نقدية.
- [ ] اختبار حجم 10,000 قيد، مع دفتر أستاذ ومصدر كل قيد وتقرير فروق.
- [ ] مراجعة محاسب مستقل للنتائج وعينة إعادة حساب يدوية.

## 2. الضرائب والفوترة السودانية — OPEN
- [ ] توثيق متطلبات ديوان الضرائب والفوترة الإلكترونية السارية وتاريخ مراجعتها.
- [ ] اعتماد معدلات/إعفاءات/تصنيفات النشاط من مختص سوداني؛ لا تُثبت نسبة عامة افتراضياً.
- [ ] التحقق من بيانات الفاتورة والتسلسل وإشعارات الخصم/الإضافة وتقارير المبيعات والمشتريات.
- [ ] توثيق رأي محاسب أو جهة مختصة؛ لا ندّعي اعتماداً رسمياً قبل صدوره.

## 3. ترقية قاعدة البيانات — OPEN
- [ ] اختبار ترقية تثبيت 2.3.13 إلى الإصدار المرشح على جهاز/بيئة واقعية.
- [ ] مقارنة عدد الصفوف والأرصدة وإجمالي المدين/الدائن قبل الترقية وبعدها.
- [ ] اختبار قاعدة قديمة فيها بيانات اختيارية/ناقصة/مكررة، وإظهار خطأ واضح عند فشل الترحيل.
- [ ] إثبات أن النسخ الاحتياطي والاستعادة يعيدان البيانات، وأن الفشل لا يفسد القاعدة الحية.

## 4. الأمن والخصوصية — OPEN
- [ ] فحص manifest للنسخة المنشورة والتأكد من إعدادات النسخ الاحتياطي الفعلية، بما فيها allowBackup.
- [ ] مراجعة أذونات Android، وتخزين كلمات المرور/المفاتيح، وتشفير قاعدة البيانات والنسخ الاحتياطية.
- [ ] التحقق من بصمة شهادة توقيع Android وثباتها عبر التحديثات.
- [ ] مراجعة مستقلة للأمن وتوثيق المخاطر المفتوحة.

## 5. توافق الأجهزة — OPEN
- [ ] تثبيت وتشغيل على ثلاثة أجهزة Android على الأقل بإصدارات مختلفة، بينها جهاز منخفض المواصفات.
- [ ] تسجيل الطراز، وإصدار Android، ورقم التطبيق، والبصمة، ونتائج كل سيناريو.
- [ ] اختبار الذاكرة/إعادة التشغيل/انقطاع الشبكة/المساحة المنخفضة والطباعة أو المشاركة حيث تدعمها الأجهزة.

## 6. الترخيص والتجربة — OPEN
- [ ] إثبات اختبار API الحي برقم تشغيل وتاريخ؛ لا تكفي الاختبارات المحلية.
- [ ] تفعيل وتجديد وانتهاء وإلغاء، وتكرار الطلب، وانقطاع الشبكة، وتغيير ساعة الجهاز للأمام والخلف.
- [ ] إثبات أن انتهاء التجربة لا يتغير بسبب ساعة الجهاز وأن السياسة عند انقطاع الشبكة واضحة.
- [ ] اختبار العميل الفعلي على جهاز، مع سجل طلبات منقح لا يكشف أسراراً أو بيانات شخصية.

## 7. الدفع والتسعير — OPEN
- [ ] اعتماد جدول موحد مكتوب: ثلاث باقات حالياً، وخيارات المدة منفصلة إن اعتمدت.
- [ ] تحديد العملة الأساسية، ومتى وكيف يُعلن سعر الصرف، ورسوم التحويل والاسترداد.
- [ ] اختبار دفع حقيقي صغير بموافقة صاحب الحساب، وإثبات الإيصال والتفعيل والمطابقة المالية.
- [ ] عدم عرض روابط بيع أو تفعيل تجاري قبل اعتماد المسار.

## 8. القانون والهوية التجارية — OPEN
- [ ] اعتماد الاسم التجاري النهائي والجهة المسؤولة وبيانات الاتصال.
- [ ] نشر سياسة الخصوصية وشروط الاستخدام وسياسة النسخ الاحتياطي/تصدير/حذف البيانات.
- [ ] مراجعة قانونية ملائمة للأسواق التي سيباع فيها المنتج، بما فيها السودان وأي سوق مستهدف آخر.

## 9. العربية وتجربة المستخدم — OPEN
- [ ] مرور موثق على كل شاشة بالعربية، واتجاه RTL، وتنسيق الأرقام والعملات والتواريخ.
- [ ] اختبار PIN والدخول والخروج واستعادة الجلسة؛ توثيق مشكلة الإغلاق السابقة إن عادت.
- [ ] اختبار طباعة/تصدير الفاتورة وPDF ومشاركة الملف، والاسم والشعار والتسلسل والحقول الضريبية.
- [ ] اختبار التنقل والعودة ورسائل الأخطاء على أحجام شاشات مختلفة.

## 10. الدعم والتشغيل — OPEN
- [ ] اختبار إرسال رسالة إلى قناة الدعم المعتمدة وتسجيل رد فعلي ومدة الاستجابة.
- [ ] اعتماد مسار البلاغات وتسجيل الأعطال وإصدار التطبيق وخطوات إعادة المشكلة.
- [ ] توثيق سياسة التعامل مع فقد البيانات، واستعادة النسخ، والتحديثات الطارئة.

- [ ] نجاح PIN وعدم الإغلاق على الأجهزة المرجعية.
- [ ] نجاح الترقية دون فقد بيانات، مع مقارنة موثقة للأرصدة والصفوف.
- [ ] اجتياز الترخيص الحي وتغيير الساعة والانقطاع.
- [ ] إغلاق البنود العشرة أو توثيق استثناء صريح وموافقة مكتوبة من المسؤولين المختصين.
- [ ] اعتماد الهوية والأسعار والشروط وسياسة الخصوصية والدعم كتابةً.
