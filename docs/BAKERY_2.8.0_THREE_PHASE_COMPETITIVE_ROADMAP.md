# المحاسب الميزان للمخابز 2.8.0 — خارطة الإنجاز التنافسية بثلاث مراحل

تاريخ التدقيق: 2026-11-06
الفرع: `release/bakery-2.8.0-financial-integrity`
طلب المراجعة: #96

## مبدأ الاعتماد
لا يُعلن الإصدار آمناً تجارياً بمجرد نجاح Gradle أو تثبيت APK على محاكي. يلزم إثبات سلامة الحسابات والبيانات على نسخة فعلية من 2.7.2، واختبار جهاز حقيقي، ومراجعة مصدرية ونتائج CI للـ commit نفسه.

## لقطة المصدر التي بُني عليها هذا التدقيق
- طلب المراجعة #96 مفتوح وغير مدمج.
- آخر commit وقت التدقيق: `b729c02fcc6fcc50d0c649a1f875c1d0afe7148a`.
- تشغيل البناء #707 على commit أقدم `dec0bdfb0cf1e524ad5f6d9e583e6c79fa59fd21` نجح.
- تشغيل البناء #709 على commit الحالي انتهى بالفشل في خطوة Smoke test signed APK on modern Android API 35.
- في التشغيل #709 نجح البناء وJVM arithmetic tests والتوقيع واختبار API 23، لكن اختبار API 35 فشل؛ لذلك تم تخطي رفع APK وسجلاته والنشر.
- تشغيل التحقق من بوابة التراخيص #260 نجح.
- سبب فشل API 35 التفصيلي لم يتوفر في بيانات الوظيفة المقروءة أثناء هذا التدقيق؛ لا يُخمن السبب.

## الموجود في المصدر — لا يعني وحده اكتمال الميزة
- SQLCipher وAndroid Keystore موجودان في `SecureDatabase.java`.
- توجد آلية ترحيل SQLite القديمة واختبار Android لقاعدة اختبار مصطنعة.
- قاعدة المخبز `almizan_bakery_250.db` وقاعدة المصنع `almizan_factory_1.db` تمران بمسار التهيئة المشفر.
- توجد دوال واختبارات حسابية للإنتاج المرحلي WIP والمرتجعات وبعض قيود المصنع.
- توجد شاشة دفتر المصنع والقيود والعكس.
- النسخة الاحتياطية JSON غير مشفرة، ويعرض التطبيق هذا التحذير صراحة.
- ملف خطة الدقة المالية يصف جداول مالية تستخدم REAL وdouble في التطبيق المحاسبي العام؛ يلزم عدم نقل هذا العيب افتراضياً إلى تطبيق المخابز قبل تدقيق كل مخزن بيانات ومسار حساب على حدة.
- الدفتر الحالي للمصنع لا يثبت وجود دفتر أستاذ متكامل يرحّل تلقائياً جميع العمليات التشغيلية. وجود جدول journal_entries أو دالة journalIsBalanced لا يثبت اكتمال المحاسبة المزدوجة.

# المرحلة الأولى — سلامة البيانات والحسابات والأمان (P0)

## 1. تثبيت خط أساس قابل لإعادة الإنتاج
- حفظ نسخة APK 2.7.2 الأصلية مع SHA-256 وشهادة التوقيع وversionCode.
- حفظ نسخة قاعدة بيانات اختبار مأخوذة من 2.7.2 مع بيانات تركيبية واقعية تشمل مخزوناً ومبيعات وديوناً وعملاء وموردين وإنتاجاً ومصنعاً.
- تعريف مخطط قاعدة البيانات لكل من المخبز والمصنع وتوثيق عدد السجلات والأرصدة قبل التحديث.
- عدم استخدام بيانات عميل حقيقية في CI أو إرفاقها بالمستودع.

## 2. ترقية قاعدة البيانات
- ترقية نسخة 2.7.2 إلى 2.8.0 دون إلغاء التثبيت أو مسح بيانات التطبيق.
- مقارنة كل سجل وحقل ومرجع ومجموع مالي ومخزني قبل وبعد.
- اختبار ترحيل قاعدة المخبز وقاعدة المصنع كل على حدة، ثم عند وجودهما معاً.
- اختبار التوقف القسري وانقطاع الطاقة والمساحة المنخفضة أثناء الترحيل.
- جعل الترحيل قابلاً للاستئناف، مع نسخة أصلية محفوظة حتى التحقق النهائي.
- التحقق من الفهارس والمشغلات والعلاقات وإعدادات WAL وforeign keys.
- اختبار ترقية قاعدة سبق ترحيلها، لمنع تكرار العملية.
- إضافة اختبار downgrade/rollback موثق، دون الكتابة فوق قاعدة أحدث بقاعدة أقدم.

## 3. التشفير وحماية النسخ
- اختبار أن ملفي قاعدة البيانات مشفران فعلياً ولا يحتويان ترويسة SQLite النصية.
- اختبار إعادة فتح القواعد بعد إغلاق التطبيق وإعادة تشغيل الجهاز.
- توثيق سلوك فقدان Android Keystore أو إعادة ضبط الجهاز؛ عدم حذف قاعدة البيانات عند تعذر فك المفتاح.
- فحص ملفات WAL وSHM والملفات المؤقتة والنسخ المرحلية وعدم ترك نسخة plaintext.
- تشفير النسخة الاحتياطية بتشفير موثق وموثوق مع كلمة مرور يختارها المستخدم، وsalt وnonce عشوائيين والتحقق من سلامة AEAD.
- دعم استعادة النسخ المشفرة على جهاز آخر بكلمة المرور، وعدم ربط مفتاح النسخة بجهاز واحد.
- إبقاء استيراد النسخ القديمة متاحاً مع تحذير واضح، وعدم اعتبارها مشفرة.
- التحقق من الملف قبل الاستعادة، ثم تنفيذ الاستعادة بمعاملة أو staging قابل للرجوع.
- اختبار كلمة مرور خاطئة وملف معدل وملف مبتور ونسخة كبيرة ونسخة قديمة.

## 4. صحة الحسابات
- تعريف سياسة دقة العملة والكمية والوحدات والتقريب صراحة.
- استخدام أعداد صحيحة بأصغر وحدة نقدية أو Decimal مضبوط؛ منع double/float في المسارات المالية.
- اختبار overflow وunderflow والقيم السالبة والقيم الصفرية والحدود الكبيرة.
- اختبار الإنتاج والقطعيات والتسعير والتالف والأجور والمصروفات واستهلاك كل خامة.
- منع ازدواج خصم التالف أو استهلاك المخزون أو تكلفة المواد.
- التحقق من تسوية النقد وبنكك والآجل والديون والتحصيل والمرتجعات.
- مطابقة تكلفة الإنتاج المرحلي وتكلفة تحت التشغيل وتكلفة المنتج التام دون فروق تقريب تراكمية.
- توثيق طريقة تقييم المخزون: متوسط مرجح أو FIFO، وعدم خلط الطريقتين.
- بناء سيناريوهات نهاية يوم وشهر مع حساب يدوي مستقل كمرجع ذهبي.

## 5. التوافق والتوقيع
- إصلاح فشل API 35 في التشغيل #709 بعد الحصول على logcat الكامل ومخرجات emulator.
- إعادة تشغيل API 23 وAPI 35 على نفس commit.
- فحص التوافق على ARM64 وواجهات ABI المدعومة فعلياً، وعدم الادعاء بتوافق جهاز لم يُختبر.
- مطابقة applicationId وversionCode وversionName وشهادة التوقيع مع النسخة السابقة.
- اختبار التثبيت فوق النسخة السابقة على جهاز فعلي، وليس محاكياً فقط.
- منع نشر APK أو Release تجاري قبل اجتياز بوابات البيانات والجهاز الحقيقي.

### بوابة خروج المرحلة الأولى
- ترقية 2.7.2 إلى 2.8.0 ناجحة على بيانات اختبار تمثل التطبيق الحقيقي، مع مقارنة آلية كاملة.
- API 23 وAPI 35 ناجحان على commit واحد.
- لا توجد نسخة plaintext أو نسخة احتياطية غير محمية معروضة على أنها آمنة.
- لا يوجد اختلاف غير مفسر في أرصدة أو كميات.
- نجاح تحديث فعلي على جهاز حقيقي موثق بصور/سجلات غير حساسة وتقرير قبل/بعد.

# المرحلة الثانية — المحاسبة المتكاملة والتشغيل الاحترافي (P1)

## 1. محرك المحاسبة
- دليل حسابات هرمي مع رموز وفئات وأرصدة افتتاحية.
- الفترات المالية وإعدادات السنة والعملة الأساسية.
- قيود مزدوجة متوازنة، مع مرجع مصدر لكل قيد.
- ترحيل تلقائي مضبوط لكل عملية بيع وشراء ومصروف وأجر ومخزون وإنتاج ومرتجع وتحويل.
- دفتر الأستاذ العام والمساعد للعملاء والموردين.
- ميزان مراجعة متوازن مع مقارنة إجمالي المدين والدائن.
- قائمة الدخل والمركز المالي والتدفقات النقدية.
- قيود الإقفال والتسوية والعكس وإعادة الفتح بصلاحيات.
- قفل الفترات المغلقة وسجل تدقيق غير قابل للمحو من المستخدم العادي.
- منع ترحيل الحركة نفسها مرتين باستخدام معرفات idempotency.

## 2. المخبز والمصنع
- فصل دفتر المخبز عن دفتر المصنع مع ربط التحويلات البينية بقيود مقابلة.
- وصفات متعددة المستويات ومقادير قابلة للقياس بدقة.
- تخطيط الإنتاج والدفعات ومراحل WIP.
- تتبع الخامات والدفعات والصلاحية والهدر والتالف.
- جرد دوري ومستمر وتسويات معتمدة.
- تكلفة معيارية وفعلية وانحرافات تكلفة.
- تكلفة العمالة المباشرة والتكاليف الصناعية غير المباشرة.
- تكلفة وربحية كل صنف ودفعة وفترة.
- مرتجعات مبيعات تعيد المخزون بتكلفة البيع الأصلية وتصحح الإيراد والتحصيل والذمم.
- أوامر شراء واستلام وصرف خامات وتحويل مخزون.
- تقارير الإنتاجية والعائد والفاقد ومعدل استخدام المواد.

## 3. المبيعات والعملاء والموردون
- فواتير وسندات قبض وصرف وإشعارات دائنة/مدينة.
- حدود ائتمان وأعمار ديون وتنبيهات تأخر.
- قوائم أسعار ومجموعات عملاء وخصومات معتمدة.
- مبيعات نقدية وآجلة ومتعددة وسائل التحصيل.
- مرتجعات جزئية وكلية ومراجعة أثرها على المخزون والربح.
- كشف حساب قابل للطباعة والتصدير.

## 4. تعدد الدول والعملات
- ملف إعدادات لكل دولة دون تثبيت ضرائب دولة واحدة في المنطق.
- عملة أساسية وعملات معاملات وأسعار صرف بتاريخ الحركة.
- فروق صرف محققة وغير محققة وفق سياسة محاسبية محددة.
- ضرائب وفواتير حسب البلد، مع قابلية ضبط محلية ومراجعة مختص.
- تقاويم ومناطق زمنية وصيغ أرقام وتواريخ ووحدات قياس.
- تقارير عربية وإنجليزية.

### بوابة خروج المرحلة الثانية
- كل عملية تشغيلية تنتج قيوداً صحيحة قابلة للتتبع.
- ميزان المراجعة متوازن.
- القوائم المالية تتطابق مع دفتر الأستاذ.
- اختبار إقفال فترة وفتح فترة جديدة دون تغيير تاريخي غير مصرح به.
- اختبار مصنع ومخبز وتحويلات داخلية دون مضاعفة الإيراد أو التكلفة.

# المرحلة الثالثة — المنتج الإقليمي والإطلاق (P2)

## 1. تجربة الاستخدام
- لوحة مؤشرات يومية واضحة وسريعة.
- واجهة عربية/إنجليزية كاملة واتجاه RTL صحيح.
- بحث عام، اختصارات، إدخال سريع، رسائل أخطاء قابلة للتصرف.
- تصميم متجاوب للهواتف الصغيرة والكبيرة والأجهزة اللوحية.
- دعم قارئ الشاشة وتباين وأحجام خطوط مناسبة.
- وضع ليلي وتخصيص وحدات القياس.

## 2. الصلاحيات والتشغيل
- أدوار مالك ومدير ومحاسب ومخزن وإنتاج ومبيعات.
- موافقات على الحركات الحساسة والخصومات والتسويات.
- سجل تدقيق مع المستخدم والوقت والجهاز والسبب.
- عمل دون إنترنت مع مزامنة اختيارية لاحقاً.
- معالجة تعارض المزامنة دون فقد أو مضاعفة الحركات.
- تعدد الفروع والمخازن مع عزل البيانات.
- طباعة وتصدير PDF وExcel واستيراد من ملفات منظمة.

## 3. التراخيص والدعم
- شهري 55,000 SDG، سنوي 550,000 SDG، دائم 1,050,000 SDG حسب سياسة المنتج المعتمدة.
- لا يمنح الترخيص الدائم إلا بعد الدفع وموافقة المالك.
- الاشتراك الشهري والسنوي لا يتحول إلى دائم تلقائياً.
- انتهاء الاشتراك يمنع الوظائف المرخصة دون حذف بيانات العميل.
- استعادة التفعيل وتغيير الجهاز وفق سياسة موثقة.
- منع التجربة المحلية من الادعاء بأنها مقاومة لإعادة التثبيت؛ يلزم تحقق خادمي إن أريد منع التحايل.
- بوابة دعم وتذاكر وسجل نسخ وإصدارات وتعليمات استعادة.

## 4. الأداء والاعتمادية
- قياس زمن فتح التطبيق وحفظ الحركات والتقارير.
- اختبار قواعد كبيرة وعمليات كثيفة وأجهزة ذاكرة منخفضة.
- مراقبة ANR والاستثناءات والتوقفات دون جمع بيانات حساسة.
- اختبارات ضغط ومدة تشغيل واستعادة بعد الأعطال.
- اختبار بطارية وتخزين وشبكات بطيئة وانقطاع الإنترنت.
- مصفوفة أجهزة فعلية تشمل Samsung وHONOR وRealme وأجهزة Android منخفضة ومتوسطة الإمكانات.

## 5. الإصدار التجاري
- مراجعة أمنية مستقلة ومراجعة محاسبية من محاسب ممارس.
- مراجعة قانونية وضريبية حسب سوق الإطلاق.

- خطة تحديث ودعم واسترجاع إصدار عند الطوارئ.

2. لا تغيير في schema أو ترحيل بيانات عميل قبل اختبار نسخة احتياطية ومقارنة قابلة لإعادة الإنتاج.
