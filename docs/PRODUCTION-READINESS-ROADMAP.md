# شركة محمد مصطفى الذكية — خطة الاعتماد التجاري

تاريخ الخطة: 2026-10-09. هذه القائمة هي سجل قبول هندسي، وليست إعلانًا بأن التطبيق أصبح جاهزًا للبيع.

## المرحلة 1 — أساس لا بيع بدونه

- [x] إزالة إذن Android `INTERNET` من Manifest الحالي لأن النسخة الحالية لا تتصل بخادم؛ يجب إعادة إضافته فقط مع ميزة شبكة موثقة ومراجعة خصوصية.
- [x] تحديث رقم إصدار Android إلى 2.2.7 ورقم البناء إلى 29.
- [x] إعداد مسار CI لا يُصدر ملفات APK/AAB ضمن المخرجات إلا بعد توقيع إصدار الإنتاج والتحقق منه؛ لا تُرفق ملفات debug في artifact الإنتاج.
- [ ] إعداد أسرار مفتاح الرفع الإنتاجي في GitHub Actions والتحقق من نجاح البناء الموقّع. لا تحفظ المفتاح أو كلمات المرور داخل المستودع.
- [ ] إنشاء/تأكيد حساب Google Play Console ورفع AAB واختباره في المسار الداخلي. النشر العام يحتاج موافقة مالك الحساب واستكمال متطلبات Play Console وسياسة الخصوصية وتصنيف المحتوى.
- [ ] ترحيل جميع مبالغ قاعدة البيانات من REAL/DOUBLE إلى أعداد صحيحة بوحدات العملة الصغرى. يتطلب هذا ترحيلًا ذا إصدار واضح، وحفظ نسخة احتياطية، وتحوّلًا محددًا للعملة/عدد المنازل العشرية، واختبارات فروق التقريب. لا يجوز مجرد تغيير نوع العمود أو ضرب القيم دون ترحيل موثّق.
- [ ] تشفير قاعدة البيانات والنسخ الاحتياطية. اختيار SQLCipher وتحديد التوافق والترخيص، ثم تصميم إدارة المفتاح وحفظه في Android Keystore؛ لا تضع المفتاح الثابت داخل الكود.
- [ ] نسخ احتياطي مجدول إلى Google Drive بعد بناء OAuth/Google Sign-In، وواجهة استعادة، وتشفير النسخة قبل الرفع، واختبار الاستعادة. لا يوجد ربط Drive فعّال في هذه النسخة.
- [ ] استبدال تجربة الأيام السبعة بترخيص إنتاجي موثّق. الاختيار بين Play Billing أو خادم تراخيص موثّق قبل كتابة التكامل؛ لا يُعد القفل المحلي الحالي ترخيصًا تجاريًا.
- [~] أُضيفت شاشة أولية لحفظ اسم الشركة ورمز العملة وعدد المنازل (0 أو 2) ونسبة الضريبة وبادئة الفاتورة، وأُضيف ترقيم للفواتير الجديدة باستخدام البادئة والتاريخ والمعرّف. لا تزال العملة والضريبة غير مطبقتين على الحسابات، ولا يوجد رفع شعار أو سجل تدقيق؛ البند غير مكتمل.

## المرحلة 2 — اكتمال المحاسبة

- [ ] عملاء وموردون بمعرّفات ثابتة، كشف حساب، حدود ائتمان، أعمار ديون، سندات قبض وصرف.
- [ ] فاتورة متعددة الأصناف، عروض أسعار، أوامر شراء، وتصدير PDF قابل للطباعة والإرسال عبر التطبيقات.
- [ ] مرتجعات وإشعارات دائنة/مدينة وإلغاء عن طريق قيد عكسي؛ منع الحذف الصامت للعمليات المرحلة وسجل تدقيق غير قابل للتعديل من الواجهة.
- [ ] حركات البنوك الجديدة تُرحّل إلى الأستاذ العام، والسلف الجديدة تُرحّل إلى حساب سلف الموظفين مقابل الصندوق. الخصومات والرواتب المستحقة والشيكات لا تزال غير مترحّلة تلقائيًا؛ أُضيف تحذير ظاهر لهذه الحدود. يلزم أيضًا اختبار عدم الازدواج والتسوية البنكية.
- [~] أُضيف اختيار فترة من/إلى بصيغة YYYY-MM-DD للتقارير الحالية، مع تطبيق الفلتر على المجاميع والتقدير الأولي وتصدير التقرير للطباعة/المشاركة. لا تزال هذه تقارير جزئية وليست قائمة دخل أو ميزانية عمومية أو تدفقات نقدية معتمدة؛ كما أن بعض القيود غير مكتملة.
- [ ] قيود يدوية، دليل حسابات قابل للتعديل بضوابط، فترات مالية وإقفال وإعادة فتح بصلاحيات وسجل تدقيق.
- [ ] مستودعات وتحويلات وجرد ودفعات وصلاحية وباركود بالكاميرا وطباعة ملصقات.

## المرحلة 3 — التميّز

- [ ] حسابات مستخدمين وأدوار وصلاحيات دقيقة.
- [ ] مزامنة سحابية آمنة متعددة الأجهزة مع طابور عمليات أوفلاين، ومعالجة تعارضات وتشفير أثناء النقل والتخزين.
- [ ] POS وطابعات حرارية واختبارات طباعة.
- [ ] عملات متعددة وأسعار صرف وتاريخ تثبيت سعر الصرف لكل معاملة، وإعدادات ضريبية حسب البلد.
- [ ] تكامل محافظ وبوابات الدفع المحلية بعد التحقق من واجهاتها الرسمية.
- [ ] مساعد عربي للبحث وإدخال البيانات بعد موافقة المستخدم، مع سجل مصدر وتأكيد بشري قبل أي ترحيل مالي.
- [ ] قوالب أنشطة وتعليمات فيديو عربية.
- [ ] اختبارات آلية، تتبع أعطال يحترم الخصوصية، دعم اللوحي والوضع الأفقي، وسياسة تحديث منتظمة.

## بوابات القبول المحاسبي والأمني

1. اختبار عمليات بيع وشراء ومصروف وسداد جزئي ومرتجع وشيك ورواتب على بيانات تجريبية.
2. التأكد أن كل عملية مالية تُرحّل مرة واحدة فقط وأن مجموع المدين يساوي مجموع الدائن لكل قيد.
3. مطابقة أرصدة العملاء والموردين والمخزون والبنوك مع الأستاذ العام.
4. اختبار حدود التقريب والمبالغ الكبيرة والعملات المختلفة بعد الانتقال للوحدات الصحيحة.
5. اختبار نسخة احتياطية مشفّرة واستعادتها على جهاز نظيف دون فقد بيانات.
6. اختبار صلاحيات المستخدم وسلامة قاعدة البيانات بعد انقطاع التطبيق أثناء الحفظ.
7. بناء Release موقّع والتحقق من التوقيع والبصمة والتثبيت والترقية على أجهزة فعلية.
8. عدم اعتماد النشر التجاري حتى تُغلق جميع البنود الحرجة وتراجع نتائج الاختبارات.

## حالة موثقة حاليًا

تم حذف إذن INTERNET من Manifest الحالي، والإصدار في المصدر 2.2.7 / versionCode 29، ورفع إصدار قاعدة البيانات إلى 6 لإضافة customer_id وsupplier_id وربط فواتير البيع والشراء الجديدة بالمعرّفات، مع ترحيل سجلات الفواتير القديمة حسب الاسم. أُضيف ترقيم للفواتير الجديدة، وتقارير أولية قابلة للتصفية بالتاريخ، وتحذيرات صريحة حول التقارير غير النهائية والشيكات والخصومات غير المرحلة. في تشغيل CI رقم 37951058741 نجح Build release only وفشل التوقيع بسبب أسرار التوقيع الإنتاجية المفقودة؛ لا توجد artifacts موقعة من هذا التشغيل. لذلك لا تُعدّ النسخة جاهزة للبيع أو النشر، ولا تُعتبر البنود المتبقية منجزة حتى تنفيذها واختبارها فعليًا.
