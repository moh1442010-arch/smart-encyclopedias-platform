# المرحلة الثالثة — الجاهزية الإقليمية والتنافسية

الحالة: بدأت أعمال التصميم والتجهيز. هذه الوثيقة لا تعني اعتماد المرحلة الأولى أو الثانية أو اكتمال وظائف المرحلة الثالثة.

## بوابة الدخول
لا يُعتمد إطلاق إقليمي ولا تُغلق المرحلتان الأولى والثانية حتى:
- نجاح البناء والترجمة واختبارات Android API 23 وAPI 35.
- نجاح التحديث فوق الإصدار السابق مع إثبات عدم فقد القيود والأرصدة والمخزون والتجربة.
- نجاح النسخ الاحتياطي والاستعادة على قاعدة بيانات فعلية، بما يشمل قاعدة المخبز وقاعدة المصنع، مع اختبار فشل الاستعادة وعدم ترك نصف حالة.
- نجاح العمل دون إنترنت وإعادة التشغيل الإجباري واستئناف العمل دون تكرار القيود.
- ربط جميع مصادر العمليات بالأستاذ العام، ومطابقة دفاتر العملاء والموردين والمخزون والإنتاج مع حسابات الأستاذ.
- اجتياز اختبارات ميزان المراجعة والقوائم المالية والفترات والعكس والتسويات.
- اختبار أجهزة فعلية وإثبات التوافق والتوقيع والتطابق بين APK المختبر والمنشور.

## مسارات المرحلة الثالثة

### 1. تعدد اللغات وإمكانية الوصول
- دعم العربية RTL والإنجليزية LTR من موارد ترجمة مستقلة، دون وضع النصوص داخل منطق الحساب.
- اختبار اتجاه الأرقام والتواريخ والعملات والطباعة في اللغتين.
- تكبير الخط ودعم قارئ الشاشة والتباين والتنقل بلوحة مفاتيح/مفاتيح خارجية عند توفرها.
- تبقى العربية اللغة الافتراضية، ولا تُعلن الإنجليزية مكتملة قبل اختبارات الواجهة والتقارير.

### 2. الصلاحيات وفصل المهام
- فرض الصلاحيات داخل طبقة الخدمات وقاعدة البيانات، لا بإخفاء الأزرار فقط.
- أدوار المالك والمدير والمحاسب وأمين المخزن والإنتاج والمبيعات والمراجع.
- سجل تدقيق غير قابل للتعديل من الواجهة لكل اعتماد أو تعديل أو عكس أو استعادة.
- اختبارات منع التصعيد والوصول المباشر للشاشات والعمليات.

### 3. الفروع والمزامنة
- كل سجل يحمل tenant/company وbranch ومعرّفاً ثابتاً ومصدر تعديل وإصداراً.
- صندوق صادر transactional outbox مع UUID فريد ومفاتيح idempotency.
- سياسة تعارض موثقة؛ لا يُستبدل قيد مالي بصمت ولا تُدمج أرصدة نقدية آلياً.
- مزامنة اختيارية مشفرة بعد عودة الإنترنت، مع إعادة المحاولة الآمنة ومراقبة فشل المزامنة.
- اختبار انقطاع الشبكة وتكرار الطلب وتزامن جهازين واستعادة نسخة قديمة.

### 4. التقارير والتبادل
- تصدير PDF وCSV/XLSX مع نطاق تاريخ وفرع وعملة أساس ومصدر واضح.
- قوالب طباعة موحدة تحمل اسم المنشأة والرقم المرجعي والتاريخ.
- استيراد مضبوط مع معاينة والتحقق من التكرار والتوازن قبل اعتماد البيانات.
- منع تصدير كلمات المرور ومفاتيح التشفير وأسرار الترخيص.

### 5. الاستعداد القانوني والأمني والتوزيع
- مراجعة الخصوصية والاحتفاظ بالبيانات وموافقة المستخدم حسب الأسواق المستهدفة.
- مراجعة الضرائب لكل دولة على حدة؛ إعداد الحقول لا يعني الامتثال القانوني.
- SBOM وفحص التبعيات والثغرات وتوقيع APK وبصمة SHA-256 وسجل إصدار.
- اختبار أداء وذاكرة وANR على أجهزة منخفضة ومتوسطة وعالية المواصفات.
- صفحة دعم وإصدارات وسياسة تحديث واسترجاع واضحة.
- مراجعة بشرية محاسبية وأمنية وقانونية قبل أي ادعاء اعتماد أو جاهزية دولية.

## قرارات محاسبية ثابتة
- لا تُستخدم أرقام floating-point في الأموال؛ تستخدم وحدات العملة الصغرى الصحيحة ودوال تحويل مضبوطة.
- تبقى SDG بوحدتها الصحيحة المتوافقة مع سجلات المخبز الحالية، ولا يُغيّر مقياسها في ترقية قاعدة البيانات دون خطة ترحيل واختبار تحويل شامل.
- USD وEUR للتسعير والاشتراكات فقط، ولا يظهران في قوائم عملات التشغيل.
- تبقى قاعدة المخبز وقاعدة المصنع منفصلتين، وتتم التحويلات بينهما بمستندين متقابلين ومعرّف ربط مشترك.
- لا يُعلن أي تقرير مالي نهائي قبل ثبوت اكتمال ترحيل كل مصادر الحركة.
