# فحص أولي لمتطلبات الدليل الإرشادي — Android وWindows
**التاريخ:** 2026-10-22  
**المستودع:** `moh1442010-arch/smart-encyclopedias-platform`  
**الفرع المفحوص:** `main`  
**الغرض:** تحديد ما يمكن إثباته من ملفات المصدر المتاحة وتحديد ما يلزم قبل إعلان فحص الهاتف وWindows مكتملًا.

## 1. ملخص تنفيذي
- تم إنشاء مسودة دليل عربي HTML قابلة للبحث والطباعة، داخل `guide/index.html`. هذا ملف محتوى ويب/مرجع؛ وجوده في المستودع **لا يثبت** أنه أُدمج داخل APK أو تطبيق Windows.
- يوجد مصدر Android رئيسي في `android-app/app/src/main/java/com/mohammedmustafa/smartcompany/MainActivity.java` وملف `AndroidManifest.xml`.
- لا تظهر نتائج البحث النصي في المستودع عن «الدليل الإرشادي» أو «الأسئلة الشائعة» قبل إضافة هذه المسودة؛ لذلك لا يوجد دليل حالي على وجود شاشة مساعدة متكاملة داخل التطبيق.
- وثيقة `windows-app/README.md` تصف نسخة Windows بأنها ما قبل الإصدار التجاري وتصرح بأن دورة دفتر الأستاذ غير مكتملة، وأن المبيعات والمشتريات والمصروفات والرواتب لا تُرحّل بعد إلى دفتر أستاذ عام متكامل، وأن اختبار الأجهزة الفعلية لم يثبت بعد. يجب التعامل مع هذه القيود كحواجز إطلاق مهمة.
- لا يمكن فحص التطبيق المثبت فعليًا على هاتف المستخدم أو تشغيل تطبيق Windows على جهاز مادي من خلال قراءة المستودع وحدها. يلزم جهاز/جلسة اختبار فعلية أو تسجيل شاشة/نتائج اختبار موثقة. لذلك فهذا **فحص مصدر ومتطلبات أولي** وليس شهادة اجتياز على الهاتف أو Windows.

## 2. ما تمت مراجعته
1. شجرة ملفات المستودع المتاحة على `main`.
2. مصدر Android الرئيسي `MainActivity.java` ومحتواه الأولي.
3. `AndroidManifest.xml`.
4. `windows-app/Program.cs` ومقدمة من واجهته.
5. `windows-app/README.md` و`SmartCompany.csproj`.
6. `windows-app.tests/WindowsAccountingTests.csproj`.
7. وجود/غياب ملفات الدليل والأسئلة الشائعة في شجرة المستودع.
8. إنشاء مسودة `guide/index.html` لتوفير محتوى عربي قابل للبحث والطباعة، مع بيان أنها تحتاج مطابقة على الواجهة الفعلية.

## 3. نتائج محددة
### Android
- التطبيق يعلن اسم «المحاسب الميزان» في Manifest.
- المصدر الرئيسي يبدو متمركزًا في ملف Java واحد كبير؛ وهذا يجعل إدخال مركز مساعدة شامل مباشرة في النشاط الرئيسي يحتاج تعديلًا حذرًا واختبارات انحدار.
- تظهر في النصوص التي تمت معاينتها مسارات تتعلق بالتجربة والترخيص والتحقق من الترخيص ومركز التحديث، ورسائل تشير إلى أن التحقق الأول أو بعد مهلة العمل دون اتصال قد يحتاج إلى إنترنت.
- لا يجوز أن يَعِد الدليل بعمل كل الوظائف دون اتصال؛ يجب اختبار كل مسار على حدة.
- لم يُثبت حتى الآن وجود أيقونة أو شاشة داخلية باسم «الدليل الإرشادي»، أو قاعدة أسئلة شائعة قابلة للبحث داخل التطبيق.

### Windows
- المشروع يستخدم .NET 8 Windows Forms وSQLite وفق ملف المشروع.
- README يذكر وحدات الأصناف والمخزون والمبيعات والمشتريات والعملاء والموردين والموظفين والرواتب الأساسية والمصروفات والنسخ الاحتياطي/الاستعادة والطباعة/البريد واللغتين.
- README نفسه يذكر صراحة أن دفتر الأستاذ في مرحلة تشخيصية، وأن الترحيل المحاسبي الكامل للعمليات غير مكتمل، وأن الملخص التشغيلي ليس قائمة دخل معتمدة.
- README يسجل كذلك أن تشفير قاعدة البيانات المحلية غير مثبت، وأن التطبيق لا ينبغي اعتباره مقاومًا لمستخدم محلي ذي صلاحيات مرتفعة أو للهندسة العكسية.
- وجود مشروع اختبارات `windows-app.tests` لا يثبت أن الاختبارات اجتازت أو أن الاختبار على جهاز Windows حقيقي تم؛ يجب فحص نتائج Actions وتسجيل نتائج تشغيل واقعية قبل الاعتماد.

## 4. تصميم مركز المساعدة المطلوب داخل التطبيق
لا يكفي فتح صفحة ويب أو ملف PDF من التطبيق. المطلوب واجهة محلية مدمجة:
- أيقونة الصفحة الرئيسية: **الدليل الإرشادي**.
- تبويبات: «ابدأ من هنا»، «شرح الأقسام»، «الأسئلة الشائعة»، «حل المشكلات»، «النسخ الاحتياطي والاستعادة»، «العمل دون إنترنت»، «الترخيص والتحديث»، «الأمان والخصوصية».
- بحث محلي فوري في العناوين والنصوص والأسئلة.
- مقالات قصيرة قابلة للطي، خطوات مرقمة، أمثلة تعليمية ببيانات خيالية، وتحذيرات قبل العمليات الخطرة.
- تشغيل المحتوى بالكامل دون اتصال، دون تحميل خارجي للخطوط أو الصور أو JavaScript أو البيانات.
- رابط «ساعدني في هذه الشاشة» يفتح مقالًا مطابقًا للشاشة الحالية عند توفر معرفات موثوقة للشاشات.
- إظهار رقم إصدار التطبيق ورقم إصدار الدليل وتاريخ المراجعة.
- زر «هل حلّت هذه الإجابة مشكلتك؟» يسجل التقييم محليًا، دون إرسال بيانات المنشأة تلقائيًا.
- خيار نسخ تقرير تشخيصي آمن يحوي إصدار التطبيق ونظام التشغيل ورمز الخطأ فقط، مع إزالة كلمات المرور ومفاتيح الترخيص والبيانات المالية.
- توفير نسخة HTML/PDF للطباعة والتنزيل، مع بقاء المساعدة الأساسية داخل التطبيق.

## 5. بنية محتوى موسعة
يجب أن يغطي الدليل جميع الوحدات الموجودة فعليًا في كل إصدار، لا قائمة ميزات نظرية:
1. البدء وإعداد الشركة واللغة والعملة والفترة المالية.
2. دليل الحسابات والأرصدة الافتتاحية والتسويات.
3. الصندوق والمحافظ والبنوك والتحويلات والشيكات.
4. العملاء والموردون والذمم والتحصيل والسداد الجزئي.
5. الأصناف والباركود والوحدات والمخازن والجرد والتالف.
6. المشتريات والاستلام والمرتجعات وتكلفة المخزون.
7. المبيعات النقدية والآجلة والفواتير والخصومات والضرائب.
8. الموظفون والرواتب والسلف والاستقطاعات.
9. المصروفات والأصول عند توفرها.
10. التصنيع المرحلي والمواد الخام والتشغيل والعمالة والمصروفات والفاقد والتالف والإنتاج النهائي.
11. دفتر الأستاذ والقيود العكسية وميزان المراجعة وحدود التقارير.
12. الطباعة وPDF والمشاركة والبريد والباركود إذا كانت مدعومة.
13. النسخ الاحتياطي والتحقق من الملف والاستعادة الآمنة.
14. الترخيص والتجربة والاشتراكات وتجديد الترخيص والعمل دون اتصال.
15. التحديث والتوافق وحل مشكلات التثبيت وعدم فقد البيانات.
16. الصلاحيات وسجل التدقيق والأمان والخصوصية، فقط بقدر ما هو منفذ فعلًا.
17. رسائل الخطأ الشائعة، أسبابها المحتملة، وإجراء آمن لكل منها.
18. الاختلافات الحقيقية بين Basic وPro وBusiness وEnterprise؛ لا يُذكر أي فرق غير مثبت.

## 6. بوابة الاختبار قبل نشر الدليل
### على Android (جهاز فعلي)
- [ ] تثبيت نظيف ثم فتح التطبيق.
- [ ] ترقية من الإصدار السابق مع التأكد من بقاء البيانات.
- [ ] ظهور أيقونة الدليل من الصفحة الرئيسية.
- [ ] فتح جميع المقالات والبحث دون اتصال بالإنترنت.
- [ ] التحقق من العربية RTL والإنجليزية LTR وحجم الشاشة.
- [ ] اختبار رابط «مساعدة هذه الشاشة» من الوحدات الأساسية.
- [ ] تجربة المسار المحاسبي على بيانات اختبار ومقارنة الأرصدة.
- [ ] اختبار النسخ الاحتياطي والاستعادة دون المخاطرة بالبيانات الأصلية.
- [ ] اختبار الترخيص في الاتصال والانقطاع ضمن سياسة المنتج.

### على Windows (جهاز فعلي)
- [ ] تثبيت نظيف وتشغيل فعلي.
- [ ] تحديث فوق نسخة سابقة مع حفظ البيانات.
- [ ] ظهور الدليل وتشغيله محليًا دون إنترنت.
- [ ] بحث المقالات والتنقل والطباعة/التصدير.
- [ ] اختبار العربية والإنجليزية والشاشات عالية/منخفضة الدقة.
- [ ] تشغيل اختبارات الحسابات وتوثيق نتيجة كل حالة.
- [ ] اختبار النسخ الاحتياطي والاستعادة ورفض الملف التالف.
- [ ] التحقق من الترحيل المحاسبي الفعلي؛ لا يُعتمد التقرير قبل إكمال هذه الطبقة.
- [ ] توثيق التوقيع وبصمة ملف الإصدار وسجل البناء.

## 7. خطة التنفيذ الموصى بها
1. تثبيت نطاق الإصدار المستهدف وتحديد قائمة الوحدات الفعلية من الواجهة والكود.
2. إكمال دليل المحتوى لكل وحدة، وإضافة الأسئلة والإجابات وخطوات الاستكشاف.
3. دمج مركز مساعدة محلي داخل Android وWindows، مع استخدام مكونات قابلة للصيانة بدل تضخيم الملفات الرئيسية.
4. ربط كل شاشة بمقالها حيث يمكن ذلك بأمان.
5. إضافة اختبارات آلية للمحتوى والبحث والروابط وعدم الاعتماد على الإنترنت.
6. إجراء اختبار جهاز حقيقي لكل منصة وتوثيق النتائج.
7. بناء الإصدار وتسجيل رقم الإصدار وCommit وSHA-256 ونتائج الاختبارات قبل نشر رابط التنزيل.
8. تحديث الدليل مع كل إصدار؛ وإظهار إشعار إذا كان إصدار الدليل أقدم من إصدار التطبيق.

## 8. معايير عدم الإعلان عن الإنجاز
لا تُعلن الميزة «مكتملة» حتى:
- تكون الأيقونة والشاشة داخل التطبيقين فعلًا.
- تعمل كل المواد الأساسية دون إنترنت.
- تكون الخطوات مطابقة لواجهات الإصدار المختبر.
- تنجح اختبارات البحث والتنقل على Android وWindows.
- تُراجع المحتويات المحاسبية من مختص، خصوصًا المخزون والتكلفة والتصنيع والترحيل والتقارير.
- تُسجل أدلة الاختبار الفعلية بدل الاكتفاء بوجود ملفات المصدر أو نجاح البناء.

## 9. ملاحظة تشغيلية
تمت إضافة المسودة الأولى في `guide/index.html` وهي قابلة للبحث والطباعة. نشرها عبر GitHub Pages، إن كان مفعّلًا، لا يساوي دمجها في APK أو برنامج Windows. كما أن إتاحتها عبر الموقع لا يجعلها متاحة دون إنترنت تلقائيًا؛ يلزم تضمين المحتوى داخل حزمة التطبيق وربطه بواجهة فعلية.
