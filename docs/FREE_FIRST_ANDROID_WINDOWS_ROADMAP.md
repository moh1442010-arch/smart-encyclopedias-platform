# خطة التطور المجانية أولًا — Android + Windows
تاريخ القرار: 2026-10-13

## القرار التجاري
لا نفترض وجود ميزانية لخوادم أو اشتراكات مدفوعة قبل أول المبيعات. تُنفّذ المرحلة الأولى بأدوات مجانية أو بخطة مجانية، ويؤجَّل أي إنفاق متكرر على البنية السحابية إلى أن تثبت المبيعات الحاجة إليه. لا نبيع ميزة غير موجودة ولا نعرض وظائف أولية كأنها نظام محاسبي معتمد.

## نطاق المرحلة الأولى
1. إتمام جاهزية Android.
2. إتمام جاهزية Windows x64.
3. اختبار محاسبي مستقل لكل منصة؛ لا نفترض أن نجاح بناء APK أو EXE يعني سلامة الحسابات.
4. توفير تثبيت واضح، وتصدير/استعادة محلية، وتعليمات عربية، وقناة دعم منخفضة التكلفة.
5. إطلاق تجريبي محدود مع عملاء مؤسسين بعد اجتياز بوابة الجودة، وجمع ملاحظات حقيقية بموافقتهم.
6. تأجيل macOS وiPhone واللغات الجديدة والتوسع العالمي حتى ثبات الإصدار الأول ووجود دخل يبرر التكلفة.

## استراتيجية التكاليف
- استخدام GitHub Actions المتاح لبناء Android وWindows ما دامت حدود الاستخدام والخطة تسمح.
- البدء بقاعدة بيانات محلية ونسخ احتياطي محلي يمكن للمستخدم تصديره، مع تحذير واضح بشأن حفظ النسخ في مكان آمن.
- عدم فرض التخزين السحابي أو المزامنة كشرط لتشغيل الوظائف الأساسية.
- لا نضيف خدمة مدفوعة أو اشتراك استضافة قبل تحديد تكلفتها وبديلها المجاني وحدود الخطة المجانية، ثم اعتماد قرار الإنفاق بناء على المبيعات.
- إذا كانت خدمة الترخيص الخلفية الموجودة تعتمد حاليًا على موارد مجانية، يجب فحص حدود الاستخدام والمراقبة والخصوصية وخطة التعطل قبل الاعتماد التجاري عليها. لا نفترض أن «مجاني» يعني غير محدود أو مضمون الاستمرار.

## الترخيص والبيع قبل وجود ميزانية
- لا نربط كل وظيفة محاسبية بالاتصال الدائم بالسيرفر.
- نبدأ ببيع يدوي مضبوط: استلام الدفع والتحقق منه، ثم إصدار ترخيص من جهة المالك، مع سجل للطلبات والإصدارات والتراخيص. لا نضع مفتاح الإدارة داخل التطبيق أو ملفات عامة.
- لا نعلن تفعيل الدفع الآلي أو التجديد الآلي ما لم يُنفذا فعليًا.
- نوضح مدة الترخيص الدائم وما يشمله من تحديثات؛ والاشتراك الشهري/السنوي لا يُباع قبل وجود طريقة عملية للتحقق من الدفع والتجديد.
- تجربة 7 أيام هدف مطلوب، لكنها لا تُعد مقاومة للتلاعب حتى يُختبر اتصالها بالخدمة الفعلية، إعادة التثبيت، تغيير الجهاز، وتوقف الاتصال.
- لا حذف لبيانات المستخدم عند انتهاء التجربة أو الاشتراك، ويجب الحفاظ على التصدير المحلي.

## بوابة جاهزية Android
- البناء والتوقيع والتحقق من package/version والـ checksums.
- اختبار تثبيت نظيف وتحديث فوق النسخة السابقة الموقعة بالمفتاح نفسه.
- اختبار عربي/إنجليزي والتنقل والعودة إلى الرئيسية.
- اختبارات معروفة النتائج للمبيعات والمشتريات والمرتجعات والتحصيلات والمدفوعات والمخزون والعملاء والموردين والمصروفات والرواتب والقيود وميزان المراجعة.
- التحقق من سلامة النسخ الاحتياطي والاستعادة وحفظ البيانات عند انتهاء الترخيص.
- إصلاح الأخطاء الحرجة قبل تسليم نسخة للعميل.

## بوابة جاهزية Windows
- البناء والتوقيع/النشر والتحقق من سلامة الحزمة.
- اختبار تثبيت وتشغيل على Windows فعلي، ومسارات قاعدة البيانات والصلاحيات والطباعة واللغة.
- مطابقة قواعد الحسابات مع Android؛ إن اختلفت بنية البيانات أو القيود، يجب توثيق ذلك واختباره بدل افتراض التطابق.
- إكمال دفتر الأستاذ العام والترحيل المزدوج قبل عرض صافي الربح أو ميزان المراجعة كأرقام محاسبية معتمدة.
- اختبار النسخ والاستعادة على جهاز آخر، واختبار فقدان/تلف الملف، والتأكد من عدم فقدان بيانات العميل.
- لا تُعلن نسخة Windows جاهزة للبيع قبل إغلاق تحذيرات README الخاصة بالقيود المحاسبية.

## معايير الانتقال إلى خدمات مدفوعة
لا ننتقل إلى استضافة مدفوعة أو مزامنة سحابية إلا عندما يتحقق واحد أو أكثر مما يلي:
- وجود مبيعات أو طلبات مؤكدة تغطي التكلفة المتوقعة.
- حاجة فعلية من العملاء لا يمكن حلها محليًا بأمان.
- الحاجة إلى ترخيص مركزي أو نسخ احتياطية مُدارة مع متطلبات موثقة.
وقبل القرار نقارن التكلفة، حدود المجاني، مخاطر الاعتماد على مزود واحد، وسياسة تصدير البيانات.

## مراحل التنفيذ
1. فحص أحدث بناء Android وWindows ونتائجهما وأصول التنزيل.
2. تدقيق الفجوات المحاسبية الحرجة في المنصتين.
3. إصلاح أخطر الفجوات أولًا مع اختبارات.
4. توحيد سياسة الإصدار والترخيص المحلي/الخلفي بما يتناسب مع التكلفة الصفرية أو شبه الصفرية.
5. إعداد حزمة إطلاق تجريبي وتعليمات النسخ الاحتياطي والدعم.
6. تجربة مع عدد محدود من العملاء، ثم إصلاح العيوب بناءً على بيانات فعلية.
7. بعد المبيعات، توسيع الخادم/السحابة، ثم دراسة macOS وiPhone والأسواق واللغات الجديدة.

## ما لا نعد به قبل التحقق
- لا نعد بأن النسختين متكافئتان وظيفيًا قبل المقارنة والاختبارات.
- لا نعد بأن الترخيص أو التجربة مقاومان للتلاعب قبل اختبار الخدمة الفعلية.
- لا نعد بتخزين سحابي أو مزامنة أو دفع آلي أو دعم مؤسسي قبل التنفيذ.
- لا نعلن جاهزية تجارية لمجرد نجاح CI أو ظهور APK/EXE.
